# 一、Skill 架构

## 1.1 目录结构

```
~/.claude/skills/human-writing-AYI/
├── SKILL.md                    228 行   主提示词
├── VERSION                       1 行   版本号（1.1.0）
├── ARCHITECTURE.md                      本文档
├── ARCHITECTURE.html                    本文档的交互图版（archify 渲染，4 泳道 × 14 节点）
├── ARCHITECTURE.workflow.json           上面那张图的规格源
├── .archify-evidence/                   图的校验截图与 receipt，不参与运行
├── VARIATION-PLAN.md           222 行   参数化改造方案（已实施，留作记录）
├── data/
│   └── weights.json            236 行   文体权重表，脚本生成
├── references/
│   ├── style-evidence.md       245 行   语料证据层
│   ├── formats-ayi.md          245 行   文体模板层
│   └── revision-ayi.md         165 行   审稿检查层
└── scripts/
    ├── build_weights.py        218 行   从语料生成权重表
    ├── pick_profile.py         353 行   稿件档案生成器 + 跨篇日志
    └── check_ayi.py            490 行   机械检查器（含繁简归一化）
```

产出目录一侧还有一份跨篇日志（不在 skill 目录里）：

```
<你的产出目录>/series-log.jsonl        每篇一行，记录用过什么，供下一篇避开
```

## 1.2 六层分层模型

整个 skill 按「加载时机」分成六层，这是架构的核心。1.0.0 只有前三层，1.1.0 加了决策层与状态层，校验层从一开始就有。

| 层 | 文件 | 加载方式 | 进不进上下文 |
|---|---|---|---|
| **提示词层** | SKILL.md | 触发时全文注入 | 进，且常驻本轮会话 |
| **知识层** | references/ 三个 md | 模型按任务需要主动读 | 只有被读到的那个才进 |
| **数据层** | data/weights.json | 只被脚本读 | 不进 |
| **决策层** | scripts/pick_profile.py | 用 bash 执行 | 不进，只有输出的档案进 |
| **校验层** | scripts/check_ayi.py | 用 bash 执行 | 不进，只有输出结果进 |
| **状态层** | series-log.jsonl | 脚本读写，放产出目录 | 不进 |

决策层和状态层是 1.1.0 加的。加它们的原因：模型自选动作会稳定收敛到偏好的那几个，
第 50 篇和第 1 篇长得一样。选择权必须从模型手里拿走，交给读日志的脚本。

这样分层的目的是控制上下文占用。全部塞进 SKILL.md 会是 900 多行，每次触发都要付这个成本；拆开之后单次典型占用是 SKILL.md 228 行加上一个 reference（165–245 行），大约 400–470 行。

## 1.3 加载优先级

```
会话开始
   └── frontmatter 的 name + description        ← 唯一常驻系统提示的部分
          │
          │  用户说触发词
          ▼
     SKILL.md 全文
          │
          ├── 需要文体模板 ────► references/formats-ayi.md
          ├── 材料过关，动笔前 ─► scripts/pick_profile.py pick（外部执行）
          │                          ▲ 读 <产出目录>/series-log.jsonl 最近五篇
          ├── 需要核规则出处 ──► references/style-evidence.md
          └── 初稿写完 ────────► references/revision-ayi.md
                                        │
                                        ▼
                                 scripts/check_ayi.py --profile --series（外部执行）
                                        │
                                        ▼
                                 scripts/pick_profile.py log ──► 回写 series-log.jsonl
```

只有 SKILL.md 与被读到的 reference 进上下文；两个脚本和日志本体不进，进的只是它们的输出。

`references/revision-ayi.md` 被 SKILL.md 明确限定在初稿完成之后才读。写作规则和审稿规则同时在场会互相干扰，模型会边写边自审，产出反而畏缩。

## 1.4 依赖关系

**对外不依赖。** SKILL.md 是自包含的，没有写「先读通用版 human-writing」。skill 是独立加载的单元，跨 skill 依赖会断链。代价是与通用版有少量内容重复。

**被外部调用。** `seo-writing-openx` 这个 skill 把正文写作环节委托给本 skill，本 skill 是它的下游组件。

**与通用 human-writing 的关系是覆盖而非继承。** SKILL.md 里有一张禁令差异表，明确列出通用版的哪四条硬禁令在本 skill 中解除。两套脚本不可混用。

## 1.5 数据来源

全部规则的取值来自一份固定语料：AYi（@AYi_AInotes）2026-03-12 至 2026-07-25 的 50 篇 X Articles，共 11.2 万中文字。其中 48 篇中文、2 篇英文版；分析时进一步剔除 13 篇「说明书腔」反面样本，有效成熟期样本 35 篇。

# 二、Skill 运行流程

## 2.1 七个阶段

### 阶段 0｜路由判断

系统提示里常驻的只有 frontmatter 的两个字段。模型靠 `description` 判断当前任务要不要调用本 skill。

因此 `description` 不是介绍文字，是路由依据，里面必须包含：适用文体清单、核心特征、与相邻 skill 的差异、触发词列表。

触发方式两种：用户显式输入 `/human-writing-AYI`，或说出「AYi 风格」「按 AYi 文风写」「AYI 体」等触发词。

### 阶段 1｜注入主提示词

SKILL.md 全文 228 行进入上下文，本轮会话内常驻。

### 阶段 2｜判定文体，加载模板

模型根据任务判定属于六种文体中的哪一种（保姆级教程 / 拆解打假 / 复盘心法 / 观点解读 / 工具清单 / 编译转译），然后读 `references/formats-ayi.md` 中对应的那一节。

混合文体可以读多节。

### 阶段 3｜材料关（闸门）

这是流程里唯一会中断写作的阶段。SKILL.md 要求动笔前必须具备两项：

- 至少一个可核对的数字锚点（能追到官方文档、财报、后台截图或自己跑出的日志）
- 至少一处使用者自己撞出来的具体细节

不具备时按顺序处理：能查的先研究，需要使用者经历的一次问完最多三个问题，两者都不行则缩小题目、缩短篇幅。

**这一阶段是强制的，不由模型自行决定跳过。** 它的作用是阻止在材料不足时硬撑篇幅。

### 阶段 3.5｜定稿件档案（强制）

材料过关后、动笔前，跑：

```bash
python3 scripts/pick_profile.py pick --genre 教程 --title "..." --length 长文 \
  --log <产出目录>/series-log.jsonl
```

脚本读日志最近五篇，输出本篇的节奏档、人称档、三到五个动作、开头类型、结尾类型、
小标题体例、立场、可用比喻域。模型照单执行，不自行改选。

日志不存在即冷启动，自由发挥。

### 阶段 4｜写初稿

按阶段 2 取得的骨架写。此时模型手上的约束有：

- 句法层九个可量化指标（段落中位字数、单句成段比例、人称密度、各类标点密度）
- 十二个标志动作，每篇只用三到五个
- 小标题四种体例，按文体选一种
- 禁令差异表（哪四条解除、哪些继续执行、哪五条是本版新增）

### 阶段 5｜自审

读 `references/revision-ayi.md`，按十二条检查表逐条过。前四条不通过就不看后面。

### 阶段 6｜机械检查

稿件落盘后执行：

```bash
python3 ~/.claude/skills/human-writing-AYI/scripts/check_ayi.py 稿件路径 \
  --profile <节奏档:人称档> --series <产出目录>/series-log.jsonl
```

`--profile` 填阶段 3.5 档案给的两个档，脚本按该档区间判；`--series` 开跨篇检查。
脚本返回统计行、「必须改」列表、「看一眼」列表。有硬违规时 `exit 1`。

繁体稿依赖 `opencc`（`pip3 install opencc-python-reimplemented`）做繁简与两岸词汇归一化；
没装时脚本会明确警告，不会静默放过。细节见 §3.9。

硬违规必须清零后重跑，warn 项由作者判断。

### 阶段 6.5｜回写日志（强制）

```bash
python3 scripts/pick_profile.py log --log <路径> --title ... --moves ... \
  --thesis "本篇的核心判断" [--portable]
```

`--thesis` 那句要先自查：把主题词换成上一篇的主题，还读得通就是可移植结论，
加 `--portable` 标记并回去重写。下一篇会因此被强制换立场。

### 阶段 7｜交付

只交作品，不展示提纲、材料清单和检查过程。来源与免责按 SKILL.md 末节规则处理：全靠公开材料的事实稿附来源，个人经历稿不附，涉及钱、健康、投资、第三方产品时免责段无例外必须写。

## 2.2 强制点与自由点

流程里有四处是硬性的，其余都交模型判断：

| 环节 | 性质 |
|---|---|
| 阶段 3 材料关 | **强制**，不满足不许进阶段 4 |
| 阶段 3.5 定档案 | **强制**，档案给什么写什么 |
| 阶段 6 硬违规清零 | **强制**，脚本 exit 1 就必须改 |
| 阶段 6.5 回写日志 | **强制**，不写下一篇就没有记忆 |
| 文体判定、动作选择、模板取舍 | 模型判断 |
| warn 项是否修改 | 作者判断 |

## 2.3 实例时间线

以 2026-08-12 产出的《x402 協議是什麼》一篇为例：

| 步 | 实际发生 |
|---|---|
| 1 | 输入 `/human-writing-AYI` 加需求（OpenX SEO 文、关键词 x402 協議、2500–3000 字）→ SKILL.md 全文注入 |
| 2 | 判定文体为保姆级教程／科普 → 读 `references/formats-ayi.md` 第一节 |
| 3 | 材料关不通过：手上无数字锚点 → 触发研究，抓 x402.org、Coinbase 开发文档、GitHub 规范仓库、Linux Foundation 新闻稿 |
| 4 | 材料齐备后，就两个会影响整篇的选择提问（语言版本、交付格式） |
| 5 | 写初稿，落盘 |
| 6 | 读 revision-ayi.md，跑 check_ayi.py |
| 7 | 脚本报「正文 3618 字超目标、单句成段偏低」→ 两轮精简 → 复跑通过 |
| 8 | 交付，附来源与免责 |

第 3 步和第 6 步是 skill 强制的，不靠模型自觉：第 3 步的研究动作由材料关触发，不是临时决定；第 6 步的机械检查有脚本兜底，硬违规不清零就不能交付。

**注意这条时间线是 1.0.0 跑的，早于阶段 3.5 与 6.5。** 放到 1.1.0 流程里，第 4 步之后要多一步
`pick_profile.py pick` 拿档案，第 7 步复跑要带 `--profile --series`，第 8 步之前要
`pick_profile.py log` 回写一行。同一个日志下的第二篇起，抽签才开始真正避开前篇。

**这也是这套东西跟「在提示词里写一句按 AYi 风格写」的根本差别。** 后者只是一个倾向，模型可以在材料不足时照写、在写完之后不自查；前者在这两个位置各架了一道闸。

# 三、各文件的作用

## 3.1 SKILL.md（228 行，主提示词）

十二节加一个小节，按执行顺序排列。

| 节 | 行数 | 作用 |
|---|---|---|
| frontmatter | 1–4 | 路由。`name` 供调用，`description` 供模型判断是否命中 |
| 蒸馏范围声明 | 10–18 | 防退化。声明语料里 13 篇说明书腔是反面样本，给一条一句话自查法 |
| 说话的人是谁 | 20–32 | 设定说话位置；划伦理边界（文风可套、经历不可套） |
| 材料这一关 | 34–42 | 前置闸门，两条硬要求加一条退路规则 |
| **先定稿件档案** | 44–79 | **1.1.0 新增。** 跑 `pick_profile.py` 拿本篇档案，以及写完怎么回写日志 |
| 句法层的硬指标 | 81–99 | 全语料中位值，用来理解基本盘；实际以档案区间为准 |
| 十二个标志动作 | 101–131 | 动作库，不是每篇的清单。每篇只用档案点到的三到五个 |
| 小标题的写法 | 133–144 | 四种体例，加格式说明（不用井号，靠空行分隔） |
| 禁令差异表 | 146–175 | 与通用版的覆盖关系：解除四条、保留若干、新增五条 |
| 六种文体骨架 | 177–186 | 每种一行骨架，详细模板指向 formats-ayi.md |
| 改稿 | 188–201 | 指向 revision-ayi.md 与脚本命令（含 `--profile`、`--series`）|
| ↳ 繁体稿：装 opencc | 203–222 | **2026-09-03 新增。** 繁体稿不归一化会选择性放水（免责触发词全漏），要求装 opencc、用 tw2sp |
| 交稿 | 224–228 | 交付边界、来源处理、免责规则 |

其中三节承担的是「防错」而非「指导」功能：蒸馏范围声明防退回说明书腔，伦理边界防把语料作者的经历安到使用者身上，禁令差异表防两套规则同时生效。

## 3.2 references/style-evidence.md（245 行，证据层）

三部分：

**① 量化结果。** 四张表——段落与句子（8 项）、标点每千字（9 项）、人称每万字（2 项）、高频标记词每万字（20 项）。

**② 文风换挡的证据。** 说明书腔那批与成熟文风那批的原文对照，各配 3–4 段引文，并给出判别方法。

**③ 逐条手法的语料出处。** 十余个动作各配 4–8 条原文引句，标注篇号；末尾附「值得单独记住的八句」。

**作用有两个，第二个更重要：**

- 让模型在需要时能取到真实语料例句，而不是自行编造「AYi 会怎么写」
- **让规则可被审计。** 规则写在 SKILL.md，出处写在这里，两边可以对账。2026-08-12 就是靠这一层发现 SKILL.md 里「自曝错误每篇都有」是精读样本偏差，实测成熟期覆盖率约 26%。

## 3.3 references/formats-ayi.md（245 行，模板层）

六种文体，每种给四块内容：

- **骨架**：编号列出段落级顺序
- **开头示例**：引用语料原文，多数给两种可选写法
- **结尾示例**：引用语料原文
- **这类稿子最容易跑偏的地方**：一句话点出常见失败模式

末尾另附一节「软广稿的写法」，五步固定流程，其中第 3 步（必有一段泼冷水）和第 5 步（单独一行披露）标注为缺一不可。

作用：把 SKILL.md 里一行骨架展开成可直接照着搭的结构。骨架和示例都锚定在具体篇号上，模型不需要凭印象推测某种文体该怎么开头。

## 3.4 references/revision-ayi.md（165 行，审稿层）

**十二条检查表**，按重要性排序，声明前四条不通过就不看后面：

| 序 | 检查项 |
|---|---|
| 1 | 段落节奏（含长段的具体拆法与改写对照） |
| 2 | 「我」和「你」在不在 |
| 3 | 数字锚点和自撞细节 |
| 4 | 泼冷水段在不在 |
| 5 | 机构腔清理（附词表与三组改写示例） |
| 6 | 结尾检查（该删什么、该留什么） |
| 7 | 比喻检查（一句判据） |
| 8 | 翻案句的密度和支撑（区分空翻与有材料的翻案） |
| 9 | 排比检查 |
| 10 | 感叹号 |
| 11 | 名词解释是否就地给出 |
| 12 | 免责与披露 |

**三种常见跑偏及修法**：写成说明书腔、套路表演、借了语料作者的生平。每种给症状、自查方法、修法。

末尾说明脚本能查什么、查不出什么（材料真假、比方土不土、泼冷水是否走流程、翻案句有无支撑，这四项只能人读）。

作用：把「改稿」这件模糊的事变成有顺序、有判据、有改写对照的清单。

## 3.5 scripts/build_weights.py（218 行，数据层生产者）

```bash
python3 build_weights.py [--corpus <语料目录>] [--out <输出路径>]
```

从语料统计出 `data/weights.json`：每种文体下十三个动作的覆盖率、节奏与人称的实际分布、
每篇命中动作数的分布、四个节奏档与三个人称档的区间定义。

语料更新或文体标注调整后重跑即可刷新。文体标注（哪一篇算教程、哪一篇算拆解）
是人工分的，写在脚本的 `GENRE` 常量里，依据是稿件的主导结构而非题材。

## 3.6 data/weights.json（236 行，数据层）

`pick_profile.py` 和 `check_ayi.py` 共同的判据来源。不手改，由上面那个脚本生成。

关键字段：`weights`（文体 × 动作的概率）、`profiles`（各文体的节奏／人称实际分布）、
`bands`（四个节奏档、三个人称档的数值区间）、`quota`（每篇该用几个动作）、
`necessity_triggered`（免责披露与清单验收件，内容需要才写，不占配额）。

## 3.7 scripts/pick_profile.py（353 行，决策层）

两个子命令：`pick` 生成本篇档案，`log` 写完之后回写一行。

**选择权在这里从模型手里被拿走。** 让模型自己挑动作，它会稳定挑同样那几个。

算法上踩过两个坑，都是实测暴露的：

- **纯 LRU 轮换会产生周期。** 池子九个、锁两篇、每篇抽三，正好切成三组固定分割然后循环，
  第 1、4、7 篇的动作组合完全相同。改成按距离衰减（上一篇 ×0.15，五篇前 ×0.9）
  加随机扰动（×0.5–1.5）。
- **衰减均等仍会整组回归。** 高权重的那几个动作衰减幅度一样，相对排序不变，
  隔一篇又一起被抽回来。补了一道组合级去重：抽出来的整组若跟最近五篇任一相同，
  换种子重抽，并把冲突组里的一个动作临时锁掉，保证组合必然不同。

随机种子取自标题而非时间，所以同样的日志加同样的标题永远得到同一份档案，可复现、可回溯。

15 篇模拟验收：动作组合去重 15/15、相邻两篇交集 0、开头 8/8 结尾 6/6 立场 5/5 小标题 6/6
全部用满、节奏四档全覆盖、动作分布极差 3。

## 3.8 series-log.jsonl（状态层，在产出目录）

每篇一行的 JSON。字段：日期、标题、文体、档案（节奏／人称／篇幅）、用过的动作、
开头类型、结尾类型、小标题体例、立场、比喻域、`thesis`（本篇核心判断）、
`portable`（这句结论换个主题是否还成立）。

**放产出目录旁边，不放 skill 目录。** 不同站点、不同栏目各用各的，否则互相污染。

`portable: true` 会让下一篇被强制换立场，并在档案里打出警告。

## 3.9 scripts/check_ayi.py（490 行，校验层）

### 用法

```bash
python3 check_ayi.py 稿件路径
python3 check_ayi.py 稿件路径 --profile 标准:平衡档
python3 check_ayi.py 稿件路径 --profile 逗号流:自述档 --series <路径>/series-log.jsonl
```

给了 `--profile` 就按该档区间判；不给则用全语料点值，且结构类指标只提示不判死
（04 那种逗号流稿子在旧版会被误判成「整体没换挡」，但那是 AYi 本人的写法）。

给了 `--series` 会做跨篇检查，报最近五篇里重复的开头、结尾、立场、动作和比喻域。
**单篇怎么看都合格，同质化只在放一起看时才显形。**

### 预处理

依次剥除：YAML frontmatter、图片标记、围栏代码块、行内代码；跳过纯链接行、表格行、引用行；标题行去掉井号后参与统计。

**繁简归一化（2026-09-03 加）。** 七张词表和三组正则都是简体。稿件检出像繁体时，先用 `opencc`
的 `tw2sp` 把正文转成简体再比对——用 `tw2sp` 不用 `t2s`，后者只转字形（網路→网路），台湾用词与
大陆用词照样对不上。不归一化的后果是**选择性放水**：繁简同形的词查得出（降本增效），不同形的全漏
（賦能、全鏈路、鑰匙），最危险的是免责段触发词「投資建議」「私鑰」「助記詞」一个都匹配不到，脚本就
不会要求写免责段。实测同一篇繁中稿，归一化前查出 5 项，归一化后 13 项。`opencc` 未安装时脚本在检出
繁体时**明确警告**，不静默放过。

### 五类检查

| 类别 | 具体项 | 级别 |
|---|---|---|
| 硬禁词 | 机构腔 27 词、模型腔路标 9 词、三条正则路标（「在这个…的时代」类）、口号词 4 个 | 前三类 error，口号词 warn |
| 结构指标 | 段落中位字数、单句成段比例、连续三段过长的位置 | 超阈值 error，接近阈值 warn |
| 密度指标 | 「你」「我」每万字、感叹号每千字、翻案句处数、四项以上同构排比、空转比喻词 | 第一人称过低 error，其余 warn |
| 内容要件 | 数字锚点数量、免责段（涉钱／健康触发）、泼冷水段 | 前两项 error，第三项 warn |
| 结尾 | 结尾三段是否落在读者身上（跳过免责段与标签行） | info |
| **结论可移植** | 结尾三段里本篇专名出现几次。一次都没有 error 级警告，少于三次给自查提示 | warn / info |
| **跨篇**（需 `--series`） | 节奏档三连、开头／结尾／立场／小标题重复、动作五篇内用满三次、上一篇 portable | warn |

### 输出与退出码

输出三段：统计行（含语料对照值）、「必须改」、「看一眼」。

- `exit 0`：无 error
- `exit 1`：有 error
- `exit 2`：文件不存在或读不到正文

### 工程细节

- 免责段判定要求「命中两个触发词，或命中一个强触发词」，避免农业类文章因为「农药」被误报
- 结尾检查前先剔除免责段与 hashtag 行，否则免责段会被当成结尾
- 硬禁词不受任何条件影响，恒为 error

### 与通用版脚本的区别

不可用通用 human-writing 的 `check_prose.py` 检查本 skill 的稿件。那个脚本把翻案句、破折号、提示性冒号列为硬违规，而这三项在本 skill 中是刻意保留的特征。

### 回归验证结果

全语料跑过：成熟期 35 篇篇均 0.40 个 error，其中 25 篇零错；说明书腔 13 篇篇均 1.85 个 error，仅 2 篇零错。
