# 模块契约

每个模块一节，固定五项：**输入 / 输出 / 委托对象 / 通过条件 / 优化挂点**。

「优化挂点」是留给后续精细优化的位置——改单个模块时只动它那一节，别动 SKILL.md 的流程骨架。
只要输入输出契约不变，任何模块都可以整块换掉。

### 闸 1.5 — 信息增益（写大纲之前）

**这是全流程唯一一道朝外看的闸。** 闸 1（M2）查的是新文跟**站内**旧文撞不撞（蚕食），
它从不问「SERP 前 10 已经写得多好、这篇有什么是他们没有的」。少了这一道，M1–M9 可以一路绿灯
产出一篇结构完美、元数据齐全、而内容 SERP 前 10 全都有的文章——只会输在排名上，且不知道输在哪一步。

落点（Vault 内，按 `article_id` 一篇一个目录）：

```
06-工作区/增益/<article_id>/gain.md
```

```bash
mkdir -p "<Vault>/06-工作区/增益/OX-xxxx"
# 在 gain.md 里写增益条目，每条一个列表项，每条带来源 URL
python3 ~/.claude/skills/seo-writing-orange/scripts/gate.py gain \
  "<Vault>/06-工作区/增益/OX-xxxx" --min-items 1
```

**`--min-items 1` 不能省** —— gate.py 默认要 3 条（1000X 口径），OpenX 侧 2026-09-03 起改为至少 1 条。

要求：**至少 1 条，每条要有可追溯出处**。两种形态任选：

| 形态 | 写法 | 适用的差异化类型 |
|---|---|---|
| 外部一手源 | 官方文档 / GitHub / 公告原文的 URL | 一手源里有、但中文圈没人写 |
| 自己的记录 | 写明实测／日志／截图／对账，**并带日期或次数** | 作者自己实测、踩坑得到的 |

**「我实测过」四个字不算**——那谁都能写。要写成「实测 47 次，2026-08-20 日志」这样能回头查的形态。
「据研究表明」「业内普遍认为」两种都不算。

**差异化不等于凭空原创。** 它在于组合、翻译、验证、判断这些动作，不在于造事实：
一手源里有但没人翻出来讲，是差异化；自己跑出来的数据，是差异化；基于有出处的事实下的判断，
也是差异化。完全无法追溯的「差异化内容」就是编的。

**外加价值条件（脚本判不了，这一步必须人／agent 判）**：每条都要说得出
**「读者缺了这条会做错什么决定、或多花多少时间」**。说不出读者的实际损失，这条就不算增益——
只数条数会把没价值的内容硬凑进来，而没人写往往正因为不值得写。

缺条目或缺 URL → `exit 1`，三个选择：

1. 回 M1 补研究，重新计数
2. 缩题——换更窄、确实有东西可说的角度，H1 一起改
3. 明确告诉主人这篇现在不建议写

**为什么不把三条增益直接写进文章 md 的一个节：** 脚本读不到就等于退回「散文里的红线」，
而那正是 orange 那边已经验证过会失效的形态（`gate.py` 开头自己写了这个失败模式）。宁可多一个目录。

**M8 要回头核对**：每条增益是否都能在成稿里找到对应段落，且**来路写进了正文**（读者能看到出处，
不是只有作者知道）。找不到 = 这道闸白列了。

### 案例计划（2026-09-18 加，方法／流程型文章必做）

大纲里凡是承诺「示范怎么做」的文章，M3 要把案例计划一起定下来，不留到 M5 临场编：

| 项 | 要求 |
|---|---|
| 品种与时间窗 | 写死交易对、周期、UTC 起止时间；数据用固定 `startTime/endTime` 抓，原始 JSON 存 `06-工作区/导出/<article_id>/data/` 并附 README 写请求参数 |
| 规则先于标注 | 用哪个周期的收盘判结构、影线算不算、区间怎么取——先写规则，再按规则逐根核 OHLC，**不要从摆动点摘要反推** |
| 三类条件 | 确认条件、失效条件（收线）、价格止损、放弃条件各自一条，不混写 |
| 时点可知 | 每个标注只能用它那个时点之前的信息；用之后的高低点划区间就是事后信息 |
| 承诺一致 | 引言承诺示范什么范围，案例就示范那个范围；示范不了的（如 15 分钟进场触发）在引言就说明留给子文 |
| 反例 | 至少一个不成立／该放弃的情形 |

**增益表述的限定**：闸 1.5 的「前 10 都没有」是选题依据，不是正文措辞。正文里「沒有一篇」「不成立」「不存在」这类范围词，
只能在紧邻有能撑住该范围的证据时用（例如「我在 X 日翻过前 10 名，没有一篇更新」），否则改成有限定的说法。D18 会查。

### H2 数量：不设固定门槛（2026-09-03 改）

**Google 从未提供「一定几个 H2」的固定配方**，研究计画 Ver.06 明确反对制定这类僵化规则。
原来的「H2 ≥4」是从 1000X 口径继承来的，没有依据，已取消。

改按这个原则判：**一个 H2 对应一个任务、一个决策点、一组比较轴，或一个高价值子问题。**
子题需要完整篇幅才能避免误导 → 拆成独立页；只是同一任务里的必要步骤 → 留在同页。
篇长由任务复杂度决定，不由字数或 H2 个数决定。

所以 OpenX 侧调 `gate.py outline` 要关掉数量门槛：

```bash
python3 ~/.claude/skills/seo-writing-orange/scripts/gate.py outline "<主题目录>" --min-h2 0
```

`--min-h2 0` 只关数量检查，**功能标题检查（纯功能 H2 ≤2 个）与自蚕食检查仍然生效**。
gate.py 默认仍是 4（1000X 口径），不传参数不会变。

**优化挂点**：目前 SERP 分析靠 WebSearch 手动看。
可接：`firecrawl-search` 批量抓 top 10、`qiaomu-seo` 做竞品结构对比、PAA 问题自动提取成 FAQ 骨架。
增益闸目前只查「条数 + 带 URL」的字面条件（价值条件判不了），不判断增益是否真的成立——可加的语义层：抓 SERP 前 10 正文
做覆盖度比对，自动指出哪一条其实别人已经写过。

**动笔前先取档案**（这一步不能跳，理由见本节末「为什么加这一步」）：

```bash
python3 ~/.claude/skills/human-writing-AYI/scripts/pick_profile.py pick \
  --genre 教程|拆解观点|复盘叙事 --title "<标题>" --length 短打|常规|长文 \
  --log "<Vault>/01-索引/series-log.jsonl"
```

递给 AYI 的五样东西，缺一不可：

0. **稿件档案** —— 节奏档、人称档、本篇只用的三到五个动作、开头／结尾类型、
   小标题体例、立场、可用比喻域。AYI 照单执行，不自行改选
1. **大纲** —— H2/H3 + 每节结论
2. **内链清单** —— 精确到「H2 + 触发词 + 锚文本」，让它写的时候就把链接嵌进句子
3. **材料清单** —— AYI 版硬要求：≥1 个可核对的数字锚点（能追到官方文档 / 截图 / 自己跑的日志）+ ≥1 处作者自己撞出来的细节
4. **GEO 结构要求** —— 调 `seo-geo-check` 的 brief 入口取得（D1、D3、D4、D7–D15）。
   这些是**结构**要求（开头要有独立速答块、每节首段先给结论、文末来源逐条可点击），
   不是文风规则——怎么说话仍然归 AYI。写前给，比写完再补有效得多：
   Answer Block 和「每节先给结论」事后补是硬塞。

### 写完之后：audit（同样委托 seo-geo-check）

```bash
python3 ~/.claude/skills/seo-geo-check/scripts/audit_d.py "<文章.md>" --stage scan
#   ↑ 机检 D 区 + 写出评审任务；然后 spawn 独立评审 subagent（只给成稿与任务文件）
python3 ~/.claude/skills/seo-geo-check/scripts/audit_d.py "<文章.md>" --stage verify
```

**只审 D 区正文。** A 区元数据、E 区 Schema 此刻还不存在（它们是 M6 产出的），审不了——
那些仍由 M6 的 `check_geo.py` 负责。

audit 不通过 → 带失败项打回本模块改稿，**上限 2 轮，第 3 轮仍不过停下来问主人**。
**审核方不许改稿**，它改了就同时是作者和评审。

audit 通过后会写出 `06-工作区/GEO自检/<article_id>.md`，M6 的 `check_geo.py` 直接读它
（D3/D7/D9/D10 四项）。E3/E4 属上稿后的项，仍需另外补。

**材料不够就先补材料。** AYI skill 明确写了：材料不足时研究、追问或缩短，绝不用重复解释灌字数。
本 skill 不替它降低标准。

**数字与判断的三条纪律（2026-09-18 加，源自三轮外部复核）：**

1. **数字锚点要么有来源，要么标为假设。** AYI 要「可核对的数字」，但「一週兩三筆」「連虧五筆是常態」「結算前 10 分鐘很容易被掃」这种没有样本的经验数字，凑进去就是事实风险。写不出来源就删，或写成「本站的筛选条件」「假设每笔亏损等于设定值」。
2. **解释模型与可观察事实分层。** 「機構在那裡建倉」「停損被觸發」是 SMC 的解释，K 线上看得到的只有价格区间与收盘。正文里第一次讲到这类说法要标明它是解释，案例里用「很可能」「符合…形态」而不是「被触发了」。
3. **改一处规则，全文 grep 旧措辞。** 案例规则从 4H 改成日线之后，「顺势上涨」「16:00 之前确定」「这一行就是你的停损」这类旧口径句子会留在别的节里。每次改规则后用 grep 把相关词全文扫一遍，复核第三轮抓到的四处全是这种残留。

### ⚠ 结构要求不是标签（2026-08-08 实测 OX-0002 时发现，优先级高于下面那节）

OX-0002 初稿被主人一次点出五处「不像人写的」，全部是同一个病：**把 GEO 结构要求与档案动作
当成要写在纸面上的标签，而不是内在的写法。**

| 纸面上写了什么 | 本来想满足的是 | 实测删掉后 |
|---|---|---|
| 引用块开头一行 `**快速解答｜<主词>**` | D1 认出 Answer Block | **D1 照样 PASS** |
| 每个 H2 首段开头 `**先給結論：**` | D3 每节首段先给结论 | **check_geo 照样 PASS 25 / FAIL 0** |
| 小标题叫「冷水　…」 | `check_ayi` 的泼冷水词表 | 词表是简体，本来就匹配不到（见下节） |
| 四个 H3 连用同一句式「這一層回答的是…」 | 让每节结论显眼 | 删掉后段落中位、单句成段全部仍在区间 |
| 开头写「先說好這篇不做什麼。」 | 档案的「开头立契约」 | 直接讲契约内容即可，不必宣告体例 |

**结论：那些标签从一开始就是多余的。** 闸检查的是结构，不是字面：

- D1 靠**引用块结构**识别 Answer Block，不看有没有标题行
- D3 要的是**首段本身有信息量、可判真假**，不是要求出现「先給結論」四个字
- 「泼一盆冷水」是**内容要求**（讲清边界与代价），不是要求小标题写「冷水」
- 「开头立契约」是**说清这篇给什么、不给什么**，不是要求写一句「先說好這篇不做什麼」

**写法**：把要求做进句子里，写完自己读一遍——**凡是「读者不需要知道、只有作者和检查脚本需要知道」
的字样，一律删掉。** 那些是脚手架，交稿前要拆。

同理，同一个句式在同一节里连用三次以上，等于把结构模板直接摊给读者看，也要换掉。

**这一条比脚本误报更值得警惕**：脚本误报只是白跑一次检查，而字面标签会真的写进上线的正文里，
并且**闸会放行**——因为闸的字面条件确实被满足了。

前者连词汇一起转（網路→网络、軟體→软件、程式介面→程序接口）。这一层依赖 `opencc`
（`pip3 install opencc-python-reimplemented`），没装时脚本会打印警告并退化为原样比对，
**不静默失效**——静默失效比报错危险，繁中稿会一直拿到不可信的结果却没人知道。

**不要为了迁就脚本去改文章用字**——那是拿正文迁就工具。

两处归一化实现是**有意重复**的（`check_geo.py` 与 `check_ayi.py` 各一份）：
human-writing-AYI 是通用写作 skill，不该反向依赖某个站点的产文脚本。8 行纯函数，
重复的代价小于错误的依赖方向。

### 为什么加「先取档案」这一步

AYI skill 1.0 把语料的概率分布压成了常数：十三个动作写成每篇都上、段落中位写死 18 字、
人称写死 88/81。实测 AYi 本人每篇只命中 3.7 个动作（中位 3），段落中位全距 7 到 156。
常数化的结果是第 50 篇和第 1 篇长得一样——一种独属于这个 skill 的 AI 味。

1.1.0 把选择权从模型手里拿走，交给读日志的脚本。日志放
`<Vault>/01-索引/series-log.jsonl`，跟其他索引台账放一起，OpenX 一份、别的站另一份，
不共用（共用会互相污染轮换）。

**边界**：档案是**流程编排**，不是文风规则。本 skill 仍然一个字都不复述 AYI 的文风规则，
文风跑偏了是 M5 的事，回去让 AYI 改稿，不要在编排层动手改。

**优化挂点**：目前是「一次性把大纲+内链+材料递过去」。
可改成分段写作（一个 H2 一次调用），好处是每段能单独验内链落地情况，坏处是段落间语气连贯性要额外照看。

## M6 · SEO 元数据与 GEO

| | |
|---|---|
| **输入** | 完整正文、主词、副词 |
| **输出** | 「上稿用 SEO 資訊」节，写在文章文件末尾（不进正文） |
| **委托** | 无（本 skill）；机检委托 `scripts/check_geo.py` |
| **通过条件** | `check_geo.py` 退出码 0（含人工项书面结论） |

```bash
python3 ~/.claude/skills/seo-writing-openx/scripts/check_geo.py "<文章.md>" --init   # 首次：生成人工项模板
python3 ~/.claude/skills/seo-writing-openx/scripts/check_geo.py "<文章.md>"          # 填完后：正式判定
```

检查项定义见 [geo-check-items.md](geo-check-items.md)——每项写明脚本实际怎么判、阈值多少、不通过怎么办。
脚本逐项检查 A（元数据）/ D（GEO 要素）/ E（Schema），**每项都打印实测值与判定依据**，不是给个结论了事。
判不了的项（D3 首段是否真给结论、D10 专有名词定义、E3/E4 上稿后 schema）要求在
`06-工作区/GEO自检/<article_id>.md` 留下书面结论，**缺答案或答案少于 8 字符照样 exit 1**——
人工项能被跳过，这道闸就退回散文红线了。

站点级的 J 区（canonical / hreflang / 列表页分页 / 全站 title 唯一）走 `check_geo.py --site`，
按站点维度确认一次，不必每篇跑。

**顺序坑（2026-09-18 已修，仍要知道）**：`audit_d.py --stage verify` 会先把 D1/D3/D4/D8/D9/D10/D15 的书面结论写进
`06-工作区/GEO自检/<article_id>.md`；旧版 `check_geo.py --init` 会把它清成空模板。现在 `--init` 只追加缺的项、不覆盖已答的，
但仍建议先跑 `check_geo.py`（不带 `--init`）看缺哪几项，再决定要不要 `--init`。
主词匹配已改为不分大小写，frontmatter 写 `smc 策略`、标题写 `SMC 策略` 不再被判未命中。

必产项：

| 项 | 要求 |
|---|---|
| Meta Title | 含主词；加站名后缀后 ≤30 全形字 |
| Meta Description | ≤155 字元；含主词；一句话给出答案而非卖关子 |
| Slug | 英文小写连字符；不含年份等会过期的词 |
| 分类 / 标签 | 分类 1 个、标签 6–10 个 |
| Schema | `Article` + `FAQPage`（FAQ 全纳入）+ `BreadcrumbList` |
| 关键词布局检查 | 主词在 H1 / 首段 / ≥1 个 H2 / FAQ；列出正文出现次数 |
| GEO 要素 | 开头 Answer Block（独立引用块，一段讲完定义）、每个 H2 首段即给结论、FAQ 一问一答、正文含 ≥10 个可查证的具体数字与日期 |

**Answer Block 是 GEO 的核心，也是内链禁区**——`backlink` 脚本会自动跳过它，不要手动往里插链接。

**优化挂点**：目前没有 SERP 标题字宽实测、没有 CTR 回流数据。
可接：标题多版本 A/B（`ab-test-setup`）、GSC 点击率回流后按表现回头改 title。

## M8 · 质检与去 AI

| | |
|---|---|
| **输入** | 成稿 |
| **输出** | 质检报告 + 是否打回 M5 的结论 |
| **委托** | `human-writing-AYI/scripts/check_ayi.py` + `article-quality-checker` |
| **通过条件** | AYI 检查通过；四维诊断无高危项；事实风险项已核；**M3 的每条增益都在成稿里找到对应段落且来路已写进正文** |

增益核对不通过 → 不是打回 M5 改文风的问题，是这篇少了当初立项的理由。
要么补写那一段，要么承认这篇的差异化没做出来，回 M3 重新想。

```bash
python3 ~/.claude/skills/human-writing-AYI/scripts/check_ayi.py <文章路径> \
  --profile <节奏档>:<人称档> --series "<Vault>/01-索引/series-log.jsonl"
```

两个参数都要给：`--profile` 让它按 M5 那份档案的区间判（不给就退回全语料点值，
逗号流档和自述档的稿子会被误判）；`--series` 做跨篇撞车检查。

AI 味超标 → **回 M5 让 AYI 改稿**，不要在编排层自己改文风。

### 内容准确性复核（2026-09-18 加，M8 第一步，在文风检查之前）

三轮外部 SEO 复核抓到的全是 GEO 独立评审拦不住的问题：结论超出来源、案例用事后信息、案例数字与数据不符、
FAQ 加了正文没有的主张、规则改了旧措辞没同步。GEO 评审只管结构，这一层要单独做：

1. **spawn 一个内容复核 subagent**，只给成稿、`06-工作区/导出/<article_id>/data/`（若有案例）与下面三个问题，不给大纲与写作过程：
   - 哪些结论超出了它紧邻引用的来源能撑住的范围？
   - 读者按正文能不能完成它承诺的任务？案例里缺哪一类条件（规则／确认／失效／放弃）？哪个标注用了当时不可知的信息？
   - 案例里的每个价位、时间与「第一次」「最高」「收破」这类时序断言，逐根对原始数据能不能核上？
2. **跑 `audit_d.py --stage scan`**，D18（绝对化表述）、D19（案例可执行）、D20（价位逐字比对）三项是这一步的机检半边。
3. **规则一致性 grep**：本篇改过的每条规则，用它的旧措辞全文搜一遍。
4. **文风检查用交付态副本**：`python3 ~/.claude/skills/seo-writing-openx/scripts/deliver_copy.py <文章.md>` 生成去掉上稿节与工作区的副本，
   `check_ayi.py` 跑那份。整份 md 直接跑会把 FAQ 长答案与上稿节算进段落中位，判错节奏档；节奏档区间是半开的（14–25 表示 <25）。

复核不通过 → 回 M5 改，改完重跑 1–3。**GEO 评审通过不等于内容正确，两道都过才进文风检查。**

**质检通过后立刻回写文风日志**，命令见 SKILL.md M8 节。一篇只写一行，打回改稿不重复写。
`--thesis` 那句要自查可移植性，换个主题还读得通就加 `--portable`。
**不回写，下一篇就没有记忆，M5 的轮换等于没装。**

**优化挂点**：目前质检在写完之后一次性做。
可改成 M5 分段写作时逐段检查，早发现早改，省重写成本。

### 脚本覆盖范围（2026-08-08 已实现）

`工具/writeback.py` 覆盖上面第 1–4 项里**照 ID 就能机械算出结果**的部分，以及第 1 项的对端对称：

| 回写项 | 脚本 | 说明 |
|---|---|---|
| 文章 frontmatter 八个字段 | ✅ | status / url / publish_date / updated / pipeline_stage / outbound_links / **category** / **author_url** |
| 对端 `inbound_links` | ✅ | 自动补，保证 scan 第 4 项对称性通过 |
| 文章总表（主记录 / 语言矩阵 / URL 登记） | ✅ | 按表头定位列，不硬编码列号 |
| 关键词登记表主词状态 | ✅ | 找不到行时报「立项时漏登记」 |
| 锚文本池 | ✅ | 传 `--anchors`；少于 3 条会警告 |
| 内链矩阵「已落实链接」明细行 | ❌ | 插入位置与锚文本只存在于正文里 |
| 内链矩阵「待补队列」勾销 | ❌ | 得先确认旧文真的改了 |
| 旧文正文插 wikilink | ❌ | 锚文本要嵌进句子，语义活 |

后三项脚本会在结尾**逐条打印待办**，不静默跳过。**它们没做完，M9 就没完成。**

完整用法：

```bash
cd "<Vault>" && python3 工具/writeback.py --article OX-0001 --lang zh-Hant \
    --status published --url "https://openx.com/x402" --publish-date 2026-08-08 \
    --outbound "OX-0002" --stage done \
    [--category 新手入門] [--author-url "<作者页>"] [--anchors "锚1,锚2,锚3"] [--dry-run]
```

`--category`（站点栏目）与 `--author-url`（作者页）是 2026-09-03 加的：
栏目在立项时可能还没定，作者页要等官网上线才有，两者都需要后补的入口。

特性：幂等（已是目标值就跳过并说明）、改动前打 unified diff、`--dry-run` 只看不写、
`--outbound` 指向不存在的 ID 或指向自己直接 `exit 2`。

**优化挂点**：内链矩阵那三项要自动化，得让 M4 的内链清单产出**结构化数据**
（目前是写在文章 md 里的表格，脚本读不回来）。若把内链清单也落成
`06-工作区/内链/<article_id>.md` 的定格式文件（参照 M3 增益闸的做法），
这三项里的前两项就能机械化，只剩「正文插链」需要人。
