# M3 · SERP 分析与大纲

这是流水线里唯一由本 skill 自己承担的写作类模块（M5 正文归 AYI，M2/M4/M9 归 Vault）。

**目标不是「看看别人怎么写」，是找出别人没答好的那部分。** 抄结构只能做出第 11 名。

---

## 一、SERP 分析（三个问题，回答完就够）

拿主关键词去搜，看 top 10。只回答这三个：

### 1. 搜到的人真正想知道什么

看 PAA（People Also Ask）和相关搜索。这批问题就是读者的真实疑问，**直接变成 FAQ 骨架**。

x402 那篇是个好例子：中文搜索结果前几页八成在聊迷因币，
所以真实读者疑问的第一位其实是「x402 是不是一顆幣、能不能買」——
这个问题成了 FAQ Q2，也成了引言的切入点。

### 2. 现有结果共同缺什么

逐条看 top 10，找**共同的空白**：

- 全都在讲是什么，没人讲怎么接
- 全都是官方文档翻译腔，没人讲踩过的坑
- 全都没给具体数字，或数字过期了
- 全都没处理某个明显的误解

**共同缺的那一项，就是这篇文章的差异化点。** 写进大纲，作为独占的 H2。

### 3. 搜索意图是哪一档

| 意图 | 特征 | 大纲重心 |
|---|---|---|
| 信息型 | 「是什麼」「怎麼運作」 | 定义 + 机制 + 边界 |
| 导航型 | 品牌名 + 功能 | 步骤 + 截图位 |
| 商业型 | 「推薦」「比較」「哪個好」 | 对比表 + 场景分流 |
| 交易型 | 「怎麼買」「怎麼開」 | 逐步操作 + 避坑 |

意图判错，结构就全错——信息型的题写成教程，读者看两段就走。

**优化挂点**：目前靠 WebSearch 手动看。可接 `firecrawl-search` 批量抓 top 10 正文做结构对比。

## 二、大纲

### 硬指标

- H2 ≥4（窄主题）／≥5（标配）
- 每个 H2 下 H3 ≥2（不强制，取决于该节复杂度）
- 每个 H2 必须能用**一句话说出结论**——说不出来的 H2 是凑数的，删掉
- FAQ 6 题左右，来自 PAA，不是自己编的
- 全文 ≥3,000 字（信息型可以更短，别为凑字数灌水）

### 必备的三块结构

**1. 开头 Answer Block**

独立引用块（`>`），一段之内讲完：定义、关键时间、治理方或出处。

它是 GEO 的核心——AI 摘要会直接抓这一段。同时它是**内链禁区**，
`backlink` 脚本会自动跳过它，不要往里插链接。

**2. 「也泼一盆冷水」那一节**

AYI 文风的硬要求，也是 SEO 上的差异化利器：top 10 里通常没人认真写限制。

写「还不能做的 N 件事」比写「N 大优势」更容易拿到停留时间，因为读者真的在找这个。

**3. 结语的下一步**

不是总结全文，是告诉读者下一步该看什么 —— 这里天然是 M4 内链清单的「下一步链」位置。

### H2 命名

- 带上主词或其自然变体，但不要每个 H2 都硬塞
- 写成读者的疑问，不是分类标签：
  - ✗ 「技術架構」 → ✓ 「一次付費請求跑了哪幾步」
  - ✗ 「優勢分析」 → ✓ 「它跟 API Key、信用卡差在哪」
- 编号 + 冒号 + 一句钩子是可用的模式（x402 那篇：`## 一、x402 協議是什麼：一個躺了二十多年的狀態碼被叫醒了`）

---

## 三、交出去之前

大纲写进文章文件，然后**立刻走 M4**。

不要跳到 M5。内链要在大纲阶段定位置——写完正文再塞，锚文本会生硬，位置总落在段尾。

移交 M4 时手上应该有：

- ☐ H2/H3 骨架，每个 H2 一句话结论
- ☐ FAQ 6 题（来自 PAA）
- ☐ 差异化点（top 10 共同缺的那项）落在哪个 H2
- ☐ 引言切入角度
- ☐ Answer Block 草稿
