# SEO / GEO 检查模组 0.3.0-beta

**只管 D 区正文（D1–D20，其中 D2 已并入 D1、D5 已删除，实际 18 项）。** A 区元数据、E 区结构化数据、J 区站点级不在本 skill 范围内——那些在 M6 由 `seo-writing-openx/scripts/check_geo.py` 负责。

原因很实际：Meta Title、描述、摘要、Schema 声明都是 M6 由编排层产出的，AYI 写完正文那一刻它们还不存在，审不了。

检查项定义全部在 [reference/check-items.md](reference/check-items.md)，那是唯一事实来源。删减讨论定了就改那一个文件。

## 两个入口

### 入口一 · `brief`（M5 之前）

把 D 区里**写作阶段能影响的项**整理成一份结构要求，交给 `human-writing-AYI` 一起写。

范围：D1、D3、D4、D7–D20（**不含 D6**，那是 M3 闸 1.5 已经做完的事，brief 里只提「你手上那条增益要写进正文并把来路写给读者看」）。

**递过去的东西必须框成「GEO 结构要求」，不是写作风格规则。** openx 红线第 2 条：文风归 AYI，编排层不许重写文风规则。D1 要求开头有独立速答块、D3 要求每节首段先给结论——这些是结构，怎么说话仍然是 AYI 说了算。

递法：读 reference/check-items.md，抽出上述项的「要求」列，按写作顺序排（开头 → 各节 → FAQ → 文末），一次性给 AYI。不要逐项解释为什么，AYI 需要的是约束不是教程。

### 入口二 · `audit`（M5 之后）

审 AYI 交出来的正文。分两步跑，中间插一次独立评审。

```bash
# 第 1 步：机检 + 生成待评审任务
python3 ~/.claude/skills/seo-geo-check/scripts/audit_d.py "<文章.md>" --stage scan

# 第 2 步：评审结果回验 + 出最终判定 + 写答案文件
python3 ~/.claude/skills/seo-geo-check/scripts/audit_d.py "<文章.md>" --stage verify
```

两步之间**必须** spawn 一个独立评审 subagent，见下节。

## 两道机制（做审核的核心，缺一不可）

七项要读懂句意，数不出来：**D1**（属哪型、缺哪几段）、**D3**（该先给结论的节）、
**D4**（FAQ 是否重复正文）、**D8**（主张有没有就近举证）、**D9**（承认边界）、
**D10**（专有名词定义）、**D15**（CTA 是否抢先／恐吓式）。交给 AI 判，但用两道机制约束。

其中 D1 / D4 / D15 是机检先粗筛、再送评审——机检结论不等于语义结论：
D1 的字数与时效标注机器能查，「属哪一型」不能；D4 的字面重合能算，「换个说法答同一件事」不能；
D15 的位置能定，「是不是恐吓式推销」不能。

### 机制一 · 独立评审（防「放水」）

`--stage scan` 会写出一份评审任务文件。拿它去 spawn subagent，**三条硬要求**：

1. **拿不到写作上下文。** 只给成稿路径和任务文件，不给大纲、不给 brief、不给写作过程。同一个上下文里既递规则又审产出，等于自己批自己的作业。
2. **默认判不通过。** 举证责任在评审方。
3. **问法反转。** 任务文件里的问法是「**找出哪几节没给结论**」，不是「是否每节都给了」。问「是不是都合格」倾向得到「是」；问「找出不合格的」才会真的去找。

评审 subagent 的产出写进 `06-工作区/GEO自检/<article_id>-评审结果.md`，格式见任务文件里的模板。

### 机制二 · 原文回验（防「编造」）

`--stage verify` 拿评审结果回原文核对：证据原句是否真实存在、D3 的证据是否真在它声称那一节的首段里。**核不上判定作废**，不是警告。

一句话：**回验保证证据不是编的，独立评审保证判定不是放水的。** 只做回验，评审方可以引用一句真实存在的过渡句当「已给结论」的证据，回验照样通过。

---

## 打回循环

audit 不通过 → 带失败项打回 AYI 改稿 → 重跑 audit。

**上限 2 轮。第 3 轮仍不通过就停下来问主人，不要继续自动重试。**

**审核方不许自己改稿。** 它改了就同时是作者和评审，两道机制白设。

## 与 check_geo.py 的接口

本 skill 的产出之一是答案文件：

```
06-工作区/GEO自检/<article_id>.md
```

`check_geo.py` 到 M6 时会读这个文件。本 skill 会填 **D1 / D3 / D4 / D7 / D8 / D9 / D10 / D15**（视触发情况），其中 check_geo.py 认的是 D3 / D7 / D9 / D10，多写的 key 它忽略、无害。

**E3 / E4 不在本 skill 范围**——它们已改由 `check_geo.py` 的在线检查抓已发布页面自动判定，不再需要人工补答案。

脚本复用而非复制：`audit_d.py` 用 importlib 加载 `check_geo.py`，直接调用它的解析函数、
`check_d` 与繁简归一化（`zh_norm`），自己只新增 D4 缺口、D8 就近举证、D12 两面、
D13–D20 与两道机制。D1 的机检（引用块结构、内链禁区、六型字数并集、时效词标日期）2026-09-19 起统一在
`check_geo.py` 的 `check_d` 里，`audit_d.py` 对 D1 只负责送评审判「属哪型、缺哪段」。**两边逻辑不漂移的前提就是复用而不是抄一份。**

## 红线

1. **不许把 A/E/J 项接过来。** 越界就会出现「AYI 写完时审 Meta Title」这种审不了的项。
2. **不许在同一个上下文里既做 brief 又做 audit 的判定。** 独立性是结构保证的，不是声明出来的。
3. **不许只做回验。** 两道机制少一道，等于没做。
4. **不许审核方改稿。**
5. **改 `check_geo.py` 必须同步 `check-items.md`。** 限制已在 2026-09-03 放宽，但两边一旦漂移，定义文件就不再是唯一事实来源。能复用就 import，别复制逻辑。

- **A10（作者与资格）已有机检**（区外，`check_geo.py`）。署名作者由安装者在 Vault 作者资料中设定；
  `author_credentials` 必须填真实内容，**不许由脚本或模型代填**——编造学经历是伪造 E-E-A-T 信号。

  繁中稿的 D4 重合率与证据回验结果此时不可信。装：`pip3 install opencc-python-reimplemented`
