# 系统维护

## 更新约定

仓库 `skills/` 是发行源。规则或脚本修改走分支和 PR，同时更新根目录 `版本更新日志.md`，记录日期、版本、影响及验证结果；涉及 skill 行为时同步对应 VERSION 和参考文档。每次安装从这一快照复制，避免只改安装目录造成下次更新丢失。

运行 `python3 -m unittest discover -s 工具/tests -v`、`git diff --check` 和 `python3 工具/openx_audit.py scan`。测试使用临时目录，不修改真实安装。空白库扫描只验证出厂结构，实际内容需在自己的 Vault 再扫描。

## 安装与回退

`bash install.sh` 跳过已有目录；`bash install.sh --force` 将旧目录移至安装目录上一级的 `.openx-install-backups/` 后安装新版本。以终端打印的路径为准。`--agents` 为两个 SEO skill 建共享入口；`--skills-dir` 与 `--agents-dir` 可指定目录。更新前确认自定义规则已保存，出现失败保留输出的备份，核对后手动恢复对应目录。安装过程不是全局事务，磁盘或权限错误可能留下部分安装。

仓库源文件保留 `<VAULT_ROOT>`，安装副本替换为仓库路径。另一个 Vault 使用 `OPENX_VAULT`；不要把个人绝对路径提交进发行源。仓库版本可用 Git 比较和恢复，文章、素材和私人索引需单独备份。

## 内容操作

- `openx_ops.py inventory` 盘点状态及发布资料缺口。
- `openx_ops.py links` 校验矩阵中已完成的链接确实存在于正文；注释、代码和工作区不算证据。
- `openx_ops.py export --article OX-0001 --lang zh-Hant --output <新文件>` 生成站点稿。先建输出目录，目标需有同语言已发布 HTTPS URL；未知锚点和图片嵌入需先人工映射。此命令不会上线。
- `openx_ops.py feedback --output <新CSV>` 为已发布文章生成待填记录；真实数据填入 `01-索引/文章效果记录.csv`，保留周期、查询或提示词、证据及后续动作。

以上脚本位于 `工具/`，用 Python 3.10+ 执行。操作其他 Vault 时将 `--vault <路径>` 放在子命令前。

`ready` 表示可交付，`published` 表示实际发布。发布回写需有效 URL 与日期，先用 `writeback.py --dry-run` 审核差异。机检通过不代表事实正确、网页可访问或 CMS 已接收，仍需完成内容复核与实际发布验证。
