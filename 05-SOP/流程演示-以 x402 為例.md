# 流程演示 · 以《x402 協議是什麼》为例

这不是模拟。OX-0001 已经真的在库里，下面每条命令你都可以自己跑一遍复现。

**分工**：本系统管闸 1（关键词）、闸 2（内链）、闸 3（回写）；`human-writing-AYI` 管正文。
两边不重叠——AYI skill 决定文章怎么说话，本系统决定文章怎么接进内容网络。

---

## 先看这篇当初缺了什么

x402 那篇的 SEO 段里，「建議內鏈」是这样写的：

```
「USDC」→ 站內穩定幣入門文
「Base」→ 站內 Base 鏈介紹文
「AI Agent」→ 站內 AI Agent 入門或工具盤點文
「鏈上手續費 / Gas」→ 站內 Gas 費說明文
「迷因幣」→ 站內迷因幣風險文
```

五条全是**类型描述**，不是文章。没有 article_id、没有插入位置、没有锚文本，
甚至不知道站内到底有没有这篇——因为写作 skill 手上没有站内文章清单。

**这就是系统补的那个洞。** 下面是有系统之后同一件事长什么样。

---

## 闸 1 · 立项前的关键词审核

### 这篇的主词该定成什么

写作 skill 在 SEO 段里写的是「主關鍵詞『x402 協議』」。闸 1 把它改了：

```bash
python3 "工具/openx_audit.py" keyword --lang zh-Hant --primary "x402 協議" --secondary "x402 教學,x402 怎麼用"
```

```
[L2] 高危 · 必须差异化（子串 / 同义组） —— 1 条
    OX-0001  主词「x402 協議是什麼」  主词互为子串
```

**判断**：主词定为长尾「x402 協議是什麼」，把「x402 協議」降到副词位当簇级词。

理由不是洁癖。如果「x402 協議」占了主词位，以后《x402 怎麼接》《x402 vs Stripe》
《x402 有哪些 facilitator》**每一篇都会 L2 撞车**——因为它们的主词都含「x402 協議」。
一个词占住了整个话题，等于把自己后面十篇文章的位置全堵死。

这个判断，写作 skill 做不了，因为它只看得见眼前这一篇。

### 下一篇立项时会发生什么

假设接着写《USDC 是什麼》：

```bash
python3 "工具/openx_audit.py" keyword --lang zh-Hant --primary "USDC 是什麼" --secondary "穩定幣,USDC 用途"
```

```
[L3b] 中危候选 · 旧文副词与本文主词高度重合，人工选一篇补链 —— 1 条
    OX-0001  主词「x402 協議是什麼」  该文副词「USDC」与本文主词高度重合 → 候选补链

结论：字面层面通过。
待办：1 篇旧文是候选补链对象，人工确认后再登记
```

**没有冲突，但产生了一个动作**：x402 那篇谈过 USDC，现在有专文了，它得链过来。

## 闸 2 · 内链设计

### 问「旧文的哪个位置该插这条链」

> **注（2026-09-11）**：下面的 `OX-0003` 是本演示录制时（2026-09-05）的存量文章编号。
> 该批 29 篇已经 旧站转换路线（2026-09-17 已整体放弃，归档于 `06-工作区/归档来源/旧站转换路线-已放弃-2026-09-17/`）的 C0 降级为外站素材（`SRC-0031`~`SRC-0059`），
> **编号作废、命令照抄会查无此文**。此处保留原样是为了让下方输出示例仍能对得上，
> 演示的是命令用法，不是可复现的数据。

```bash
python3 "工具/openx_audit.py" backlink --lang zh-Hant --target OX-0003 --keyword "AI Agent"
```

```
  OX-0001  x402 協議是什麼？一次看懂這套讓 AI 自己付錢的網路支付標準
       跳过  第 6 行 ｜ Answer Block／引用块
            原句：> x402 協議是一套開放的網路原生支付標準…
     → 建议插这里  第 66 行 ｜ 正文
            所在 H2：## 二、x402 協議怎麼運作：一次付費請求的完整流程
            原句：假設有個天氣 API，查一次收 \$0.001。你的 AI Agent 想查台北明天會不會下雨。
       备选  第 112 行 ｜ 正文
            所在 H2：## 三、x402 協議解決了什麼：跟 API Key、信用卡差在哪
       跳过  第 243 行 ｜ 附录（常見問題）
       跳过  第 263 行 ｜ 附录（上稿用）
```

从「站內 AI Agent 入門文」变成了「**第 66 行、H2 二、这句话里**」。

注意它主动跳过了 Answer Block——那个引用区块要保持干净给 AI 摘要抓，
插内链会破坏它；FAQ 和上稿信息段同理，插了对读者动线没用。
这条规则不靠记性，写进脚本了。

### 系统发现了一个写作时看不见的问题

x402 第 54 行那**一句话**：

> **第二，用穩定幣結算。** 目前主力是 USDC 和 EURC，跑在 Base、Solana 這些鏈上…

《USDC 是什麼》《穩定幣支付》《Base 鏈是什麼》三篇专文都想往这句插链。
三篇都写完之后，一句话里三条站内链——密度爆表，读者被打断三次。

**处置**（已记进 [内链矩阵](../01-索引/内链矩阵.md)）：只留 USDC 那条，
Base 改插到 H2 二讲结算的部分，穩定幣支付那条放弃。
这个决定必须在《USDC 是什麼》**立项时**做掉，不是三篇写完再回头补。

单看一篇文章，这个问题不存在。只有站在全站视角才看得见。

## 闸 3 · 回写

四张表全部回写，`article_id` 分配到 OX-0001，下一个可用 ID 递增为 OX-0002。
然后跑体检：

```bash
python3 "工具/openx_audit.py" scan
```

```
[5] 孤儿文章与出链数
    [孤儿] OX-0001 无入链
    [无出链] OX-0001
```

诚实的结果：全站第一篇，没有入链也没有出链。
这不是 bug，是内容网络的起点该有的样子。

## 意外收获：内链缺口 = 最好的选题池

x402 想链但站内没有的五篇文章，直接变成了选题池，
写进了 [02-主题簇/AI 與加密支付](../02-主题簇/AI%20與加密支付.md)：

| 候选主词 | 优先级 | 为什么 |
|---|---|---|
| AI Agent 支付 | **P0** | 本簇 pillar，缺它 OX-0001 的上行链无处可链 |
| USDC 是什麼 | P1 | x402 全文提最多次的概念 |
| 穩定幣支付 | P1 | 同上 |
| Base 鏈是什麼 | P2 | — |
| Gas 費是什麼 | P2 | x402 有整个 H3 在讲 gas |
| 迷因幣風險 | P2 | x402 引言就在处理「x402 是不是一顆幣」的误解 |

**这批选题的需求已经被验证过了**——不是猜读者想看什么，
是上一篇文章写到那里、确实需要一篇能链过去的文章。

## 下次写新文章的完整动线

```
1. 定题 → 跑 keyword（闸 1）
     ↓ L1/L2 未解决就停在这里，别往下写
2. 过闸 → 建 03-文章/<lang>/OX-xxxx-<slug>.md，status: idea
     ↓ 这步不能省，不建文件脚本就看不见这篇，下一篇会漏判
3. M3 SERP 分析与大纲 → 由 seo-writing-openx 做（不是 AYI，AYI 只接 M5 正文）
     ↓
4. 大纲出来 → 跑 links + backlink（闸 2），产出两张内链表
     ↓ 位置精确到行号 + H2 + 原句
5. M5 交给 human-writing-AYI 写正文，内链按表插（递大纲+内链清单+材料清单）
     ↓ 用 [[wikilink]]，URL 定了再换真实链接
6. 写完 → 回写四张表 + 真的去改旧文补链（闸 3）
     ↓
7. 跑 scan 确认没留孤儿、没有不对称链接
```

翻译走 [SOP-4](SOP-4-多语言同步.md)：内链关系不重新设计，只换锚文本；
目标文章的该语言版本不存在，那条链就删掉、进待补队列。
