# SOP-3 · 存量文章导入

**执行时机**：拿到已发布文章清单时。
**为什么重要**：闸 1 的审核结论只有在存量全部入库后才可信。存量没进来之前，每篇新文都可能撞到系统看不见的旧文。

---

## Step 0 · 用户提供什么

任一形式都行，按信息完整度从好到差：

1. **站点 sitemap.xml 或文章列表 URL** —— 最好，能拿到全量 URL + 标题。
2. **本地目录（docx / md）** —— 丢进 `06-工作区/待导入/`。
3. **一份表格**（标题 / URL / 主关键词）—— 最省事但最容易漏副关键词。

至少要有：**标题 + URL（或 slug）+ 语言**。主关键词缺失可以推断，但要标记为「推断值」待人工确认。

## Step 1 · 落到暂存区

所有原始文件放 `06-工作区/待导入/`，不要直接扔进 `03-文章/`。
导入完成并校验通过后再移入。

## Step 2 · 逐篇提取元数据

每篇提取：

| 字段 | 来源 |
|---|---|
| `title` | 原文 H1 |
| `lang` | 目录 / 内容判断 |
| `slug` `url` | 原 URL |
| `primary_keyword` | 优先取原 SEO 设置；没有则从 H1 + 首段推断，**标记 `[推断]`** |
| `secondary_keywords` | 从 H2 标题 + 高频名词提取，3–8 个 |
| `cluster` | 按主题归类；归不进现有簇的先记为 `未分簇` |
| `publish_date` | 原文 |
| `anchor_offers` | 依据 H1 与主词生成 ≥ 3 条 |

**跨语言配对**：同一篇文章的不同语言版本必须分配**同一个 `article_id`**。
配对依据：URL 结构对应关系 > slug 相似 > 标题语义对应。配不上的暂时各自独立，标记 `待配对`。

## Step 3 · 分配 ID 并写索引

按导入顺序连续分配 `OX-xxxx`，更新 `文章总表` 底部的「下一个可用 ID」。
三张表全部写入：`文章总表`（主记录 + 语言矩阵 + URL 登记）、`关键词登记表`（主词 + 副词）、`术语与锚文本表`（锚文本池）。

## Step 4 · 全量冲突扫描（关键）

```bash
python3 "工具/openx_audit.py" scan
```

存量里**几乎一定存在历史蚕食**——两三篇文章抢同一个词，是长期写作的常态。
逐条按 SOP-1 的四级标准判定，输出一份《存量关键词冲突清单》到 `06-工作区/审核报告/`。

处置**不要求立刻全改完**，但要求：
- L1 冲突全部登记进 `关键词登记表` 的「待仲裁冲突」表；
- 每条给出处置意见和优先级；
- **在仲裁完成前，涉及这些词的新文一律不许开题。**

## Step 5 · 重建内链矩阵

从存量正文里抽出**已存在的**站内链接，回填 `内链矩阵` 的链接明细，并跑体检：

- 孤儿文章（inbound = 0）→ 列出来，安排补链。
- 出链 = 0 的文章 → 同上。
- 死链（指向已删除页面）→ 列出来清理。
- 每个簇是否有 pillar；pillar 是否链到了簇内每一篇子文。

补链动作全部写进「待补链接队列」，分批清。

## Step 6 · 移入正式目录

校验通过后，文件按 `03-文章/<lang>/OX-xxxx-<slug>.md` 命名移入，清空 `06-工作区/待导入/`。

校验清单：
- ☐ 每个文件 frontmatter 字段齐全
- ☐ `article_id` 无重复、无跳号
- ☐ 每个 `primary_keyword` 在同 lang 内唯一（或已登记为待仲裁）
- ☐ `cluster` 都指向存在的簇文件
- ☐ `outbound_links` / `inbound_links` 互相对称（A 链 B，则 B 的 inbound 含 A）
