# SOP-2 · 内链设计

**执行时机**：大纲确定后、写正文之前。发布后再执行一次「反向部分」。
**为什么在大纲阶段做**：内链要长在内容的骨头上。写完再硬塞，锚文本会很生硬，位置也总是落在段尾。
**输出**：两张表（新文→旧文 / 旧文→新文），写进本次审核报告，并同步到 `01-索引/内链矩阵.md`。

---

## A 部分 · 新文 → 旧文（写作时插入）

### A1 · 拉候选池

```bash
python3 "工具/openx_audit.py" links --lang zh-Hant --cluster "主题簇" --keywords "主词,副词1,副词2"
```

脚本按三个信号排候选：同簇优先 → 关键词交集 → pillar/子文关系。

### A2 · 三类必链（不是可选项）

| 类型 | 规则 |
|---|---|
| **上行链** | 本文若是子文，**必须**有且仅有一条链向本簇 pillar。位置：引言之后的第一个 H2 内，或首个需要背景铺垫的地方。 |
| **前置知识链** | 大纲里凡是「读者需要先懂 X 才能看下去」的地方，若 X 已有专文，**必须**链过去。位置：该概念**首次出现**的那句话。 |
| **下一步链** | 结语或 FAQ 前，链向读者读完本文的自然下一步（通常是同簇兄弟文）。 |

### A3 · 定位到具体位置

逐条填这张表，**位置必须精确到 H2/H3 标题名 + 触发词**，不能写「文章中部」：

| 目标文章 | 目标主词 | 插入 H2/H3 | 触发词（正文里出现该词的第一处） | 锚文本 | 类型 |
|---|---|---|---|---|---|
| OX-0001 | OpenX 註冊 | H2「開始交易前的準備」 | 「註冊」 | OpenX 註冊教學 | 簇内-兄弟 |

锚文本从目标文章的 `anchor_offers` 里取（见 `01-索引/术语与锚文本表.md`），
并查 `内链矩阵` 看这个锚文本是否已被用过太多次——同一目标全站同锚文本占比 ≤ 40%。

### A4 · 密度体检

- 每 800 字 ≤ 2 条站内链
- 单篇出链 3–8 条
- 同一目标全文只链 1 次（首次出现处）
- 无 `點這裡` / `了解更多` 类锚文本

超标就砍**弱相关**的那几条，优先保留三类必链。

### A5 · 写法

URL 未定阶段，正文一律用 Obsidian wikilink：

```markdown
先完成 [[OX-0001-openx-signup|OpenX 註冊教學]]，再回來看這一步。
```

发布时按 `01-索引/文章总表.md` 的「已发布 URL 登记」把 wikilink 换成真实链接：

```markdown
先完成 [OpenX 註冊教學](https://.../openx-signup)，再回來看這一步。
```

## B 部分 · 旧文 → 新文（发布后必须回头改）

**这是绝大多数内容系统烂掉的地方。** 只往外链、不往回链，新文永远拿不到站内权重。

### B1 · 找出该改哪些旧文

三个来源：

1. **SOP-1 的 L3 命中** —— 旧文副词 = 新文主词的，全部。这是最高优先级。
2. **同簇 pillar** —— pillar 文必须补一条下行链指向新文，无条件。
3. **脚本扫描** —— 旧文正文里出现过新文主关键词、但当时没有专文可链的地方：

```bash
python3 "工具/openx_audit.py" backlink --lang zh-Hant --target OX-0002 --keyword "新文主词"
```

### B2 · 逐条定位并真的改掉

| 待改旧文 | 出现位置（H2 + 原句片段） | 插入锚文本 | 类型 | 已改 |
|---|---|---|---|---|
| OX-0001 | H2「註冊完成後」…下一步是完成身分驗證… | OpenX 身分驗證流程 | 簇内-兄弟 | ☐ |

改的时候注意：
- 只改**首次出现**处，不要一篇旧文里塞三条指向同一新文的链接。
- 改完检查旧文自身的出链总数没有超过 8 条；超了就把旧文里最弱的一条删掉。
- 更新旧文 frontmatter 的 `outbound_links`，以及新文的 `inbound_links`。

### B3 · 清空待补队列

`内链矩阵.md` 中本篇可执行项须实际落实后标完成；未立项/未发布/缺语言的依赖保留原因，不假勾销、不阻塞无关文章。完成后跑 `python3 工具/openx_ops.py links`，已完成行须有对应语言正文真实链接，代码/注释/工作区不算证据。历史无语言列的矩阵核源语言，译文记录增加 `lang` 列。

## C 部分 · 多语言的内链

**不要为每种语言重做一遍内链设计。**

- 链接关系（谁链谁、插在哪个 H2）在源语言层定死，各语言版本原样继承。
- 翻译时唯一要换的是**锚文本**：从目标文章**该语言版本**的 `anchor_offers` 里取。
- 若目标文章的某语言版本**还不存在**，该语言版本的这条内链**删掉**，不要链到不存在的页面，也不要跨语言链。
- 删掉的链接记进 `内链矩阵` 的待补队列，等目标文章的该语言版本上线后补。

详见 [SOP-4](SOP-4-多语言同步.md)。
